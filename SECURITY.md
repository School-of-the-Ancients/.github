# Security reporting

These repositories include prototypes and experiments; no response-time guarantee,
security certification, maintenance term, or vulnerability bounty is offered.

If the affected repository offers Security -> Report a vulnerability, use that
private channel. Otherwise open an issue asking for a private reporting channel
without posting exploit details, keys, private records, or identifying images.
Send the affected revision, impact, and a minimal synthetic reproduction once
a private channel is agreed. This policy does not authorize testing systems or
accounts you do not own or have permission to test.

Keep credentials in appropriate private configuration, not commits or screenshots.
A public-source license does not authorize access to the creator's computer,
cloud services, learner data, or third-party accounts. Refer to each app's actual
security and remote-access documentation before deploying it.
